# Darina Danilyuk — портфолио

Сайт-шоурил: первый экран — чёрно-белые портреты, дальше по скроллу идут
фильмы, каждый показан «нарезкой» из 29 кусков — миксом, как трейлер, с разным
ритмом склеек (от коротких вспышек до долгих кадров). Затем
экран-анонс для работы, которая ещё не вышла, и подвал.

Механика листания повторяет главную страницу
[alextakacs.com](https://alextakacs.com/#5): экран на весь вьюпорт, один жест
прокрутки = один экран, переход 700 мс, якоря `#1 … #N` в адресной строке.

## Как работает нарезка

Для каждого фильма движок:

1. читает длительность видео и делит её на **29** равных кусков —
   кусок `i` начинается в `i × (длительность / 29)`;
2. перематывает в начало куска, показывает из него `CUT_SECONDS` секунд
   исходника и режет на следующий — по кругу `0 → 1 → … → 28 → 0`;
3. держит `playbackRate = 1.28`, то есть кусок в 1.6 с исходника
   занимает 1.25 с реального времени.

Играет только видео активного экрана, соседние подгружаются заранее.
Справа внизу — 29 рисок, текущая подсвечена акцентом.

Это описание режима «сырой» нарезки, когда сайт сам прыгает по фильму, куски равные,
по порядку. На сайте сейчас готовые файлы (см. ниже): в них куски идут не по порядку
фильма и разной длины — см. «Порядок кусков» и «Ритм склеек».

Ничего не режется на файлы: движок прыгает по `currentTime` одного видео,
поэтому фильм можно заменить, не пересобирая сайт.

## Готовая нарезка

Полный фильм на сайт класть не нужно: зритель вытянет сотни мегабайт ради
36 секунд, а сам фильм окажется в открытом доступе целиком. Поэтому нарезку
можно посчитать заранее и отдать сайту один маленький файл:

```bash
# 29 кусков по 1.6 с из диапазона START..END, каждый ускорен в 1.28
python3 - <<'EOF' > filter.txt
START, END = 19.0, 182.5          # границы без заставок и чёрного
CUTS, RATE, CUT_SEC = 29, 1.28, 1.6
seg = (END - START) / CUTS
p = [f"[0:v]split={CUTS}" + "".join(f"[s{i}]" for i in range(CUTS)) + ";"]
for i in range(CUTS):
    p.append(f"[s{i}]trim=start={START+i*seg:.4f}:duration={CUT_SEC},"
             f"setpts=(PTS-STARTPTS)/{RATE}[v{i}];")
p.append("".join(f"[v{i}]" for i in range(CUTS)) + f"concat=n={CUTS}:v=1:a=0,format=yuv420p[out]")
print("".join(p))
EOF
ffmpeg -i master.mp4 -filter_complex_script filter.txt -map "[out]" -an \
  -c:v libx264 -preset slow -crf 25 -movflags +faststart film.mp4
```

Границы `START` и `END` ищутся так: `ffmpeg -i master.mp4 -vf
blackdetect=d=0.6:pix_th=0.06 -f null -` покажет чёрные поля, а глазами
нужно отсечь ещё возрастную плашку и заставку студии — иначе они попадут
в нарезку и будут бить вспышкой на тёмном сайте.

### Порядок кусков: микс, как в трейлере

В готовой нарезке куски идут **не по ходу фильма**, а миксом: начало, середина,
конец, снова начало, снова середина… Так превью не пересказывает сюжет по порядку и
ощущается трейлером. `tools/montage.py` делает это сам (`--order mix`, по умолчанию):

- фильм делится на три зоны — куски 0–9 (начало), 10–19 (середина), 20–28 (конец);
  в нарезке они идут по кругу, зона за зоной;
- порядок внутри зоны подбирается перебором так, чтобы соседние куски были непохожи
  (разные люди, место, свет), два тёмных не шли подряд, а куски, стоявшие в фильме
  рядом, рядом не оказывались; нарезка зациклена, поэтому конец сравнивается и с началом;
- первым всегда стоит самый первый кусок фильма;
- `--seed N` даёт другой вариант, `--order chrono` — прежнюю хронологию,
  `--order 0,10,20,…` — свой порядок вручную.

### Ритм склеек: от вспышек до долгих кадров

Склейки идут с разной динамикой, как в трейлере, а не по метроному. Ритм задан кривой
`PACE_TRAILER` в `tools/montage.py` (`--pace trailer`, по умолчанию; `--pace even` —
все куски по 1.25 с, как было): три «волны» — кусок за куском всё короче (от ≈1.5 с до
≈0.4 с), потом долгий кадр-вдох (≈1.8 с), и снова разгон; в конце долгий кадр, который
зацикливается на начало. Всего получается ≈25 с вместо прежних 36.

- **Короткий кусок** — середина прежнего окна в 1.6 с при том же ×1.28, так что кадр, по
  которому подбиралось кадрирование для телефона, остаётся в нём.
- **Долгий кусок** — всё окно, чуть замедленное (не медленнее ×0.85: при большем
  замедлении кадры начинают дёргаться).
- **Подбор места.** Порядок выбирается с оглядкой на ритм: спокойные кадры (без
  движения) попадают на долгие места, а тёмные на долгие не попадают.
- **Края окна.** Чёрное по краям и заставка студии вырезаются сами: окном становится
  самый длинный ряд подряд идущих кадров без чёрного и без заставки (красно-зелёно-
  голубой логотип узнаётся по трём цветам сразу). Раньше «Драйв» при каждом круге начинал
  с вспышки логотипа и чёрной паузы, а «Кирилл» — с полусекунды чёрного. Если заставка
  нашлась посередине куска, скрипт предупредит, а начало куска можно срезать вручную
  (`--skip 0=0.75`).
- **Постер** берётся из середины куска 0, а не с фиксированной секунды: первый кусок
  бывает короче секунды.
- **Границы кусков** (`cutTimes`) скрипт после кодирования находит сам: из всплесков
  разницы кадров строится цепочка стыков, расстояния между которыми близки к задуманным
  длинам. Искать каждый стык отдельно по плану нельзя — у «Драйва» исходник с
  переменной частотой кадров, ошибка копится, и к концу плановые места уходят от
  настоящих на десятые доли секунды. Без `--durations` `tools/cuts.py` ждёт равные куски
  и на микс-нарезке откажется работать.

Скрипт печатает `cutOrder` — какой по счёту кусок фильма стоит на месте `j`. Он
записан в `films.js` для справки (сайт его не читает). **После пересборки в другом
порядке** нужно пересчитать `cutTimes` (`tools/cuts.py`) и перенести `focus`: он задан
по месту в нарезке, а не по куску фильма (правило — в шапке `films.js`).

Такому файлу в `films.js` ставится `prerendered: true`: движок его не
перематывает, а просто крутит по кругу и ведёт индикатор по таймкоду.
Зритель видит ровно то же, но вместо гигабайта качает несколько мегабайт.

## Кадрирование на вертикальном экране

Кадр у фильмов горизонтальный («Кирилл» — широкий, 2.35:1), а телефон держат
вертикально: кадр масштабируется по высоте, а по бокам обрезается, так что виден
только узкий срез — у «Кирилла» около 20 % ширины, у «Драйва» около 26 %. Раньше
брался срез по центру, а режиссёр ставит героев по третям — в середине часто было
пусто.

Теперь у **каждого из 29 кусков нарезки своё положение среза**. В `films.js` у
фильма есть строка `focus` — по числу на кусок: где в кадре (в % ширины, слева
направо) держать центр. 50 — середина, 0 и 100 — самые края. Правило
`@media (max-aspect-ratio: 1 / 1)` в `styles.css` читает значение, которое движок
кладёт в `--fx`; на горизонтальных экранах оно не работает — там кадр виден целиком.

Как это устроено, и почему не проще:

- **Центр, а не object-position.** Окно слева равно `(1 − w) · p`, где `w` — видимая
  доля кадра. Если подставить `c %` прямо в `object-position`, окно сдвинется к
  середине, и герой у края встанет на самую границу. Движок считает
  `p = (c − w/2) / (1 − w)` и подставляет его заново при каждом изменении окна
  (поворот телефона, панели браузера): `w` зависит от пропорции экрана.
  Положения подбирались и проверялись для самого узкого экрана (0.46, 390×844);
  на более широком окне видно больше, и герой остаётся в кадре.
- **Ровно на стыке.** Куски в готовом файле — не равные доли (после кодирования
  сдвиг бывает до двух кадров), поэтому у фильма есть `cutTimes`: время начала
  кусков 1…28 из самого файла (`python3 tools/cuts.py assets/films/<имя>.mp4`).
  Кадрирование меняется через `requestVideoFrameCallback` — в тот же кадр, что и
  склейка. Где этого API нет, окно переключается по `currentTime`, и на стыке
  картинка может на кадр-два «подъехать» раньше времени. Если файл пересобрали
  (`tools/montage.py`), `cutTimes` пересчитывается, иначе стыки поедут.
- **Постер.** Пока видео не заиграло, постер стоит в окне куска 0, чтобы при
  появлении видео ничего не сдвигалось.

Положения подобраны по самим кадрам: для каждого куска смотрелись начало, середина
и конец, и окно ставилось так, чтобы лицо героя не прижималось к границе ни в один
из этих моментов. Там, где в куске меняется план или герой проходит через весь
кадр, одно положение — всегда компромисс (так у «Кирилла» куски 6 и 9, у «Драйва»
6, 12, 20, 21 и 25); можно поправить.

**Поправить любой кусок** — открыть `tools/focus.html` (двойной щелчок, работает с
`file://`). Выбрать фильм, нажать на нужный кусок и двигать окно мышью по кадру или
стрелками ← → (Shift — по 5 %), ↑ ↓ — следующий кусок; «начало / середина / конец»
показывают три момента куска. Справа — ровно то, что увидит телефон. Внизу готовая
строка `focus: [...]`: скопировать и вставить в `films.js`. Правки хранятся в браузере,
пока их не вставили.

## Языки

Сайт на восьми языках: русский, английский (британский), испанский,
баскский, итальянский, французский, немецкий и арабский (саудовский).

Все тексты — в `i18n.js`, по одному блоку на язык. Код править не нужно:
добавить язык — дописать блок и его код в `I18N_ORDER`. Если строки нет,
подставляется английская, потом русская.

```js
'en-GB': {
  label: 'Eng', dir: 'ltr',
  about: 'about', contact: 'contact',
  kinds: { short: 'short film', mv: 'music video' },
  soon: 'soon',
  langNav: 'Language',                         // подпись панели с кнопками языков для читалки экрана
  watch: 'Watch the film',                     // ссылка «смотреть» в описании фильма
  shots: ['green screen', 'pre-shoot', ...],   // подписи плиток по порядку
}
```

Язык берётся из сохранённого выбора, иначе из языка браузера (`de-AT`
подхватит `de`), иначе первый в списке. Выбор запоминается в `localStorage`.

**Арабский переворачивает раскладку.** `dir="rtl"` на `<html>`, боковые
ссылки и подпись фильма меняются местами, индикатор нарезки уезжает влево.
В вёрстке для этого используются логические отступы (`inset-inline-start`
вместо `left`), поэтому зеркалится всё само. Разрядка и капитель для
арабского отключены: арабские буквы соединяются, и `letter-spacing` их
разрывает. В шрифтовой стек добавлены Tahoma и Geeza Pro — в Verdana
арабицы нет.

Подписи `about` / `contact` висят у краёв экрана и в разных языках сильно
разной длины. Сетка стены считает место по самой длинной, поэтому на узком
экране схлопывается в одну колонку — проверено на всех восьми.

**Названия фильмов не переводятся** — см. «Названия, „смотреть“ и ссылка на фильм»:
у каждого фильма одно оригинальное и одно официальное английское. **Русского на нерусских страницах
нет:** там показано только английское название, а кнопка русского подписана «Rus».

**Кнопки языков.** На телефоне все восемь стоят в одну строку на всю ширину, каждая
высотой 44px (поровну делят ширину; на самом узком экране, 320px, выходит по 39px в ширину). Раньше
были две строки по 19–22px: мельче минимума WCAG 2.2 (критерий 2.5.8 «размер цели
нажатия» — от 24×24), попасть пальцем было трудно, а две строки ещё и наползали на
портрет. Выросла зона нажатия, а не буквы: они только на 1px крупнее (10px вместо 9px). Мышью
кнопки не ниже 32px, а на сенсорных экранах любой ширины (`pointer: coarse`, например планшет) — 44px.

**Зоны нажатия вообще.** Тот же замер по всем экранам и панелям нашёл то же у стрелки
вниз, крестика закрытия, правовых ссылок подвала («куки» — 21px в ширину) и у «о фильме».
У них зона нажатия увеличена внутренними полями с таким же отрицательным внешним отступом:
вид и раскладка прежние (положение текста сверено с прежней версией до полупикселя).
Название-ссылка на экране фильма сделано с таким же запасом по высоте.

## Первый экран

Портреты вертикальные, а экран обычно горизонтальный. Поэтому первый экран
собран не из одиночных кадров, а из **склеек**: в каждой один, два или три
портрета, стоящих в ряд во всю высоту. Ширина у каждого своя, по пропорции
кадра, — ничего не обрезается и не плющится.

Белые поля, которые Дарина оставила на снимках, работают промежутком между
кадрами, поэтому **стык между соседними кадрами растушёвывать нельзя**: лица
начнут просвечивать друг через друга. Размывается только внешний край ряда,
чтобы он растворялся в размытой подложке.

Склейки задаются в `films.js` номерами кадров:

```js
window.HERO = {
  photos: ['assets/portraits/darina-01.jpg', ...],
  sets: [[2], [0, 1], [2, 0], [1, 2, 0], ...],   // 1, 2 или 3 кадра
};
```

Первая склейка — один крупный план. Дальше они сменяют друг друга каждые
6.5 с. Чтобы добавить портрет, достаточно положить файл в `assets/portraits/`,
дописать его в `photos` и составить новые `sets`.

На вертикальном экране (телефон) ряд не нужен: показывается первый кадр
склейки во весь экран, остальные скрыты.

## Названия, «смотреть» и ссылка на фильм

**У фильма два названия, и во всех языках они одни:** оригинальное (`title` в `films.js`)
и официальное английское (`titleEn`) — у «Кирилла» «Кирилл, моя любовь» и «Kirill, my love»,
у «Драйва» «Драйв» и «Drive». Прежде названия были переведены на все восемь языков («كيريل، حبيبي»
по-арабски, «Kirill, mi amor», «Kirill, ene maitea», «Kirill, meine Liebe» и так далее), и один
фильм числился под восемью именами: фестивали и базы ищут по оригиналу и по английскому, лишние
варианты только размывали поиск. Поэтому группа `films` из `i18n.js` удалена, а переводить
названия новых фильмов не нужно. Английское название — то, что стоит у фильма на ютубе. Переводятся
только подписи вокруг: вид («короткий метр»), синопсис, ссылка «смотреть». У клипа название
`MPMGA OUTRO` совпадает в оригинале и по-английски, второй строки у него нет.

**Что показано на какой странице.** Русский — только на русской странице. На ней стоит оригинал,
а под ним мелко английское. На остальных семи — одно английское название, кириллицы нет нигде: ни в
тексте, ни в подписях для читалки экрана, ни в заголовках. Какое показывать, решает `titleLang` в
`films.js` (язык оригинала): страница на этом языке получает оригинал и английское, прочие — английское.
Русская подпись кнопки языка «Рус» на нерусских страницах пишется латиницей «Rus» (поле `labelOther`
в блоке `ru` в `i18n.js`), а название площадки VK — «VK Видео» только по-русски, на остальных «VK Video».
Проверено обходом всех экранов, панелей, документов подвала и вкладок клипа на семи языках:
кириллицы нет ни в тексте, ни в атрибутах (`alt`, `title`, `aria-label`).

**Где ссылка на полный фильм.**

- **На экране фильма — само название, выделенное маркером.** Полоса цвета акцента по нижней части
  строки, как отчёркнутое маркером слово; прежде вместо неё было красное свечение, и оно выглядело
  дёшево. Полоса вычерчивается слева направо один раз, когда экран открывается (справа налево — в
  арабском); на телефоне наведения нет, поэтому она постоянная. При наведении и фокусе заливает строку
  целиком. При «уменьшить движение» она стоит сразу, без вычерчивания. Если строка переносится, полоса
  у каждой своя. В режиме высокой контрастности, где фон стирается, ссылку отличает подчёркивание.
  Отдельной кнопки на экране нет, и это нарочно. Маркер настраивается в `styles.css`:
  `.film-title a.t .t-text` — цвет `--mark`, положение и высота полосы (`0 96% / 100% 48%`).
- **В описании («о фильме») под синопсисом стоит строка «СМОТРЕТЬ ФИЛЬМ 5:45 ↗»** на всех восьми
  языках (у клипа — «Смотреть клип»). Это текст того же голоса, что «о фильме» на экране: мелкие
  прописные, подчёркнуто слово, время и стрелка тоном тише; без рамки, фона и значка. Зона нажатия 44px
  высотой. Заголовка «о фильме» / «о клипе» над названием в описании больше нет (и так понятно);
  в разметке он остаётся скрытым для читалки экрана. Хронометраж — поле `duration` в секундах, и это
  длительность **видео по ссылке** (ютуб показывает её под плеером), а не мастера: у «Драйва» мастер 3:08,
  а на ютубе 2:59 (без заставки и титров). Сейчас: «Кирилл» 5:45, «Драйв» 2:59. Нет `duration` — строка
  остаётся без времени.
- **Ссылок может быть несколько:** `links: [{ url: … }, { url: … }]` — VK первым, в России YouTube
  грузится плохо. В описании встанет по строке на каждую, с названием площадки; её сайт берёт из адреса
  сам (VK, YouTube, Vimeo, иначе имя хоста), подписи в данных не нужны. У клипа ссылок пока нет — и строки
  нет, она появится сама, когда заполнят `links`. Те же `links` покажутся на экране-анонсе.
- **Читалке экрана** название-ссылка произносится как «Кирилл, моя любовь — Смотреть фильм, 5:45 —
  YouTube (откроется в новой вкладке)»: видимый текст стоит в начале имени (WCAG 2.5.3).

## Превью ссылок (Open Graph)

Ссылка в Telegram, WhatsApp и соцсетях показывается карточкой с картинкой. Карточку собирает
робот из тегов `<meta property="og:…">` в `<head>` у `index.html`. Скрипты робот не выполняет,
поэтому теги статичные — **один язык на страницу**: русский и английский вместе («Дарина Данилюк —
режиссёр / Darina Danilyuk — film director»). Остальные языки переключаются уже на самом сайте.

- **`og:image`** — `assets/og/og-darina.jpg`, 1200×630, меньше 100 КБ. Два кадра: «Кирилл»
  (героиня, 86-я секунда мастера) и «Драйв» (герой, 24-я), поверх рукописная подпись Darina
  Danilyuk (`assets/logo-darina.svg`) и «РЕЖИССЁР · FILM DIRECTOR»; над каждой половиной название
  фильма (оригинал и английское). Картинку собирали отдельно, скрипта в репозитории нет. Чтобы
  заменить, достаточно положить в `assets/og/` новый JPEG 1200×630 (до 300 КБ) и поправить имя в
  тегах `og:image`, `og:image:secure_url`, `twitter:image` и в JSON-LD. Имя лучше менять (например,
  `og-darina-2.jpg`): Telegram и соцсети запоминают картинку по адресу.
- **`og:title`, `og:description`, `og:url`, `og:type`, `og:site_name`, `og:locale`** (русский основной,
  семь остальных — альтернативные), **`og:image:width/height/type/alt`**, **`twitter:card`**
  (`summary_large_image`), **`canonical`**.
- **JSON-LD (schema.org)** там же: Person и два Movie — у каждого фильма `name` (оригинал) и
  `alternateName` (английское), хронометраж и ссылка. Это те же данные, что в `films.js`; при правке
  одного править и другое.

**Адреса в тегах абсолютные, и сейчас они на демо-домене** `https://darina-danilyuk.vercel.app`: Open
Graph требует полный URL, по относительному пути картинка в превью не попадёт. Когда появится
настоящий домен, заменить его во всём `index.html` (og:url, og:image, twitter:image, canonical, JSON-LD)
одной командой:

```bash
sed -i 's#https://darina-danilyuk.vercel.app#https://настоящий-домен#g' index.html
```

и убрать из `vercel.json` заголовок `X-Robots-Tag: noindex` — его поставили на время демонстрации, а с
ним поисковики сайт не покажут.

Telegram запоминает превью ссылки. После правки тегов или картинки обновить его можно, отправив
ссылку боту @WebpageBot. Проверить, что видит робот: `curl -A 'TelegramBot (like TwitterBot)' <ссылка>`.

## Как поставить настоящие фильмы

1. Положите файлы в `assets/films/`. Лучше два формата на фильм:
   `.webm` (VP9 — легче) и `.mp4` (H.264 — нужен Safari).
2. Опишите их в `films.js`:

```js
{
  id: 'moy-film', kind: 'short', year: 2025,
  title: 'Название',                     // оригинальное; переводить не нужно
  titleEn: 'Official English title',     // официальное английское — второе и последнее
  duration: 179,                         // секунд, у полной версии по ссылке — на кнопку «смотреть»
  src: ['assets/films/moy-film.webm', 'assets/films/moy-film.mp4'],
  poster: 'assets/films/moy-film.jpg',   // кадр, пока видео грузится
  link: 'https://www.youtube.com/watch?v=...',   // необязательно: название и кнопка «смотреть» станут ссылкой
}
```

Число фильмов любое — экраны и якоря пересчитываются сами.
Если файла нет или формат не поддерживается, экран покажет постер и подпись
«видео не найдено», остальной сайт продолжит работать.

Пересобрать оба формата из исходника:

```bash
ffmpeg -i source.mov -c:v libx264 -crf 22 -pix_fmt yuv420p -an -movflags +faststart moy-film.mp4
ffmpeg -i source.mov -c:v libvpx-vp9 -crf 33 -b:v 0 -row-mt 1 -an moy-film.webm
```

Дорожка звука не нужна: видео играет с `muted`, иначе браузер запретит автоплей.

## Описание работы

Бэкстейдж живёт в описании своей работы — кнопка «о фильме», а у клипа «о клипе».
Отдельного экрана внизу у него нет. Снятые фильмы и клип устроены по-разному.

**Снятый фильм** — прежняя страница: синопсис, лента кадров («как это снималось»),
титры списком. Лента прокручивается вбок, страница при нужде вертикально.

**Клип** — страница без прокрутки: три вкладки.

- «история» — слова Дарины слева и кусок самого клипа справа (видео без звука,
  по кругу; вырезан из присланного файла с первого непустого кадра, 2.2 с), под ним
  подпись «кадр из клипа». Последняя строка «Премьера скоро.» набрана как плашка
  «скоро» на экране анонса. Текст лежит в `i18n.js` (`clipStory`, три абзаца) и
  переведён на все восемь языков; данные вкладки — `story` в записи клипа в `films.js`.
  На телефоне кадр стоит над текстом и **не пропадает ни на какой высоте**: он
  забирает то место, что осталось после текста — на высоком экране 16:9 по ширине, на
  низком ужимается (по высоте обрезается, `object-fit: cover`), но остаётся не ниже
  64px. На невысоком телефоне (до 760px) подпись «кадр из клипа» убирается, а набор
  чуть плотнее. Если текст всё же не влезает (итальянский и французский на телефоне
  ниже 700px, любой язык на 320×568), прокручивается сама вкладка без полосы — кадр
  уезжает вместе с ней.
- «как это снималось» — бэкстейдж, листалка со стрелками и счётчиком.
- «из инстаграма» — посты-анонсы: плитки ведут на пост, у рилсов метка воспроизведения.

Листалка не прокручивается, а переходит: ряд лежит в окне с `overflow:hidden` и
сдвигается на целый кадр стрелками, колесом вбок, клавишами ←/→ и перетаскиванием
мышью или пальцем. Высота кадров — вся свободная высота вкладки, ширина по
пропорции, поэтому ничего не режется и страница не прокручивается при любом окне и
размере шрифта. Край, за которым ряд продолжается, уходит в тень. По клику кадр
открывается в просмотрщике — целиком, со счётчиком и автопрокруткой; Escape закрывает
слои по одному: сперва просмотр, потом описание.

Управление просмотром — одна тёмная таблетка под кадром: «заново», «назад», «пуск /
пауза», «вперёд». Кнопки крупные — 56px, «пуск» 68px (цель нажатия по WCAG 2.2 — от
44px); на низком окне (до 560px высотой, телефон на боку) 48 и 56px. Раньше над
таблеткой стояла ещё пара стрелок ← →, то есть «назад» и «вперёд» были дважды. Кадр
по высоте ограничен так (`100vh − 276px`), чтобы вместе с подписью, счётчиком и
таблеткой он всегда помещался в окно. Клавиши ←/→ и пробел работают как раньше.

```js
bts: [
  { cover: 'assets/wall/shoot-01.jpg', shot: 0 },   // shot — подпись из i18n
]
posts: [
  { cover: 'assets/wall/ig-01.jpg', url: 'https://www.instagram.com/…', kind: 'video' },
]
```

Посты-анонсы: обложки **скачаны**, а не прилинкованы — инстаграм отдаёт их по
подписанным ссылкам, которые протухают.

## Экран-анонс

Работа, которую ещё рано показывать, описывается в `films.js`:

```js
{
  soon: true,
  kind: 'mv',                   // вид работы — запасной вариант, если артисты не названы
  id: 'mpmga',                  // служебный ключ
  title: 'MPMGA OUTRO',         // название на экране; оно же и по-английски — titleEn не нужен
  artists: 'uniqe, nkeeei & ARTEM SHILOVETS',  // на экране — «by …» под названием
  note: '',                     // например «13 октября»
  creditsKey: 'clipCredits',    // строка «Режиссёры: …» — на странице клипа
  story: { ... },               // вкладка «история» на странице клипа
  bts: [...], posts: [...],     // вкладки «как это снималось» и «из инстаграма»
  links: [],                    // [{ url: 'https://vk.com/video…' }, { url: 'https://youtu.be/…' }]
  src: [...], poster: '...',    // подложка экрана: бэкстейдж, не сам клип
}
```

Экран читается сверху вниз и держится на трёх строках: крупное красное «скоро»
над всем, под ним название и мелко «by …» с исполнителями. Больше на нём ничего
нет: режиссёры и подробности живут на странице клипа, а отдельной кнопки «о
клипе» нет — **название и есть кнопка**, оно открывает эту страницу. Подчёркивание
у названия едва заметное, при наведении или фокусе загорается красным; ссылки на
сайте везде подчёркнуты, и здесь то же правило. Слово «by» лежит в `i18n.js`
(`soonBy`) и пока одинаково во всех языках — при желании его можно перевести.

Такой экран не заводит движок нарезки и не показывает индикатор. Пока `title`
пуст, «скоро» становится единственным заголовком, ещё крупнее, и тогда оно само
открывает страницу клипа.

Названия и псевдонимы не переводятся и не приводятся к верхнему регистру:
`artists` печатается ровно так, как стоит на странице трека на стриминге.
Порядок имён в трио меняется от трека к треку — у «MPMGA OUTRO» первым идёт
`uniqe`, — поэтому его сверяют со страницей именно этого трека, а не по
памяти. Переводится вокруг них только обвязка: «скоро» и «by».

## Шрифт по языку

У каждого языка свой шрифт. Шрифты системные и проприетарные: вшить их в
сайт нельзя, а подгружать со стороны — значит потерять открытие с `file://`.
Поэтому стек локальный: сперва названный шрифт, за ним ближайшее из того, что
обычно стоит в системе. Единственное исключение — английский: у Comic Sans есть
свободный двойник (Comic Neue, лицензия OFL), он лежит в `assets/fonts/` вместе с
текстом лицензии и подключается через `@font-face` из подпапки — с `file://` это
работает.

| язык | шрифт |
|------|-------|
| рус  | Verdana (как было) |
| eng  | Comic Sans MS, иначе Comic Neue (из `assets/fonts`), иначе Papyrus |
| esp  | Optima (родная для macOS; на Windows — Segoe UI); в заголовках — Jokerman, иначе Hobo |
| eus  | Karako (баскская наборная традиция), иначе Rockwell |
| ita  | Monotype Corsiva, иначе Brush Script MT |
| fra  | Didot (родная для macOS; на Windows — Bodoni MT из Office); в заголовках — Mistral |
| deu  | Rotis SemiSerif, иначе Candara |
| عربي | Simplified Arabic, иначе Traditional Arabic |

У Monotype Corsiva (итальянский) и Mistral (французские заголовки) очень
маленький строчный рост: при тех же 10–15px, что у Verdana, текст не читается.
Поэтому каждый `font-size` в `styles.css` записан как `calc(Npx * var(--tx, 1))`, а
множитель `--tx` задан по языку: 1.4 для `it`, у остальных 1. Французский — по
модели испанского: заголовки остаются на Mistral (на них `--tx: 1.4` задан прямо
у элементов), а основной текст набран Didot, у которой нормальный рост, но тонкие
волоски, — для него мягкая прибавка 1.15. Подбирать числа нужно в одном месте,
вверху `styles.css`. Коэффициенты выбраны по особенности гарнитур, а не по
отрисовке: Corsiva, Mistral и Didot на машине разработки не установлены, поэтому
перепроверить глазом стоит на машине, где они есть.

Почему у английского появилась своя копия: Comic Sans MS стоит на Windows и macOS, но
не на телефонах. На iPhone вместо неё подставлялся Papyrus, на Android — системный
«cursive», и английский на телефоне выглядел иначе, чем на компьютере. Comic Neue
стоит в стеке сразу за Comic Sans и скачивается только там, где её нет (и только
при английском языке). Это близкий по рисунку шрифт, а не сам Comic Sans: у него
чуть уже буквы, и купленный шрифт Microsoft вшить нельзя. У остальных языков такого
двойника нет (Jokerman, Mistral, Rotis, Karako и Corsiva лицензируются), поэтому на
телефонах они по-прежнему могут отличаться от компьютерных.

Optima — родной шрифт macOS и iOS, на Windows её по умолчанию нет; там для
испанского подставляется Segoe UI. Запасные испанского и немецкого намеренно не
пересекаются: на машине без обоих основных шрифтов эти языки иначе выглядели бы
одинаково.

Связное письмо — французский, итальянский и арабская вязь — не терпит
разрядки и прописных: буквы расцепляются. Для этих языков `body.is-script`
снимает `text-transform` и `letter-spacing` с мелких подписей. Переключатель
языков исключён: это коды, они должны выглядеть одинаково везде.

## Подвал и правовые документы

Последний экран — подвал, собранный по образцу `deblock.com`: контакты,
черта, правовые ссылки, подпись, копирайт и имя во всю ширину, уходящее
вниз в тень (та же рукописная подпись, что на первом экране).

Боковые ссылки «о себе» и «контакты» — 15px, а область нажатия доведена
до 44×44 CSS-пикселей (усиленный уровень WCAG 2.2, критерий 2.5.5; минимум
по 2.5.8 — 24×24). Текст при этом стоит на прежнем месте: отступ от края
уменьшен ровно на величину бокового поля.

Боковые ссылки стоят по центру высоты у самых краёв, и текст подвала не
должен попадать под них. На экранах шире 720px это решает горизонтальный
отступ блока (зона ссылок минус внешнее поле; на широком мониторе поле само
больше зоны, и ничего не меняется). На телефоне увести текст по горизонтали
нечем — ссылки занимают почти всю ширину, — поэтому подвал там состоит из двух
групп: контакты над полосой ссылок, документы под ней. Полоса — средний ряд
сетки, симметричный экрану, как и сами ссылки; имя уходит под текст фоном.

Контакты в подвале набраны тем же подчёркнутым текстом, что и боковые
ссылки, — один стиль на весь сайт. Высота имени внизу ограничена 38% экрана:
без потолка на широком мониторе оно вырастало почти во весь вьюпорт и
выдавливало контакты под переключатель языков.

Четыре документа — условия использования, конфиденциальность, куки и
правовая информация — лежат в `i18n.js` (`legal*` и `legal*Text`) и
открываются оверлеем на языке посетителя. Тексты описывают то, что сайт
делает на самом деле: он статический, ничего не собирает, кук не ставит и
держит в браузере одну запись — выбранный язык.

Если на сайте появятся формы, счётчики или аналитика, тексты надо
переписывать: сейчас они верны именно потому, что ничего этого нет.

## Настройки

Верх `films.js`:

| Параметр       | По умолчанию | Что делает                                  |
|----------------|--------------|---------------------------------------------|
| `CUTS`         | `29`         | на сколько кусков режется фильм             |
| `RATE`         | `1.28`       | скорость воспроизведения                    |
| `CUT_SECONDS`  | `1.6`        | сколько секунд исходника показывать в куске  |
| `SCROLL_SPEED` | `700`        | мс на перелистывание экрана                 |

`CUTS`, `RATE` и `CUT_SECONDS` можно переопределить у отдельного фильма
полями `cuts`, `rate`, `cutSeconds`.

Если `CUT_SECONDS` больше или равно длине куска (`длительность / 29`),
фильм играет подряд без склеек — как на референсе. Чтобы нарезка была
заметна, нужна длительность больше `CUTS × CUT_SECONDS` ≈ 47 с.

## Управление

Колесо и свайп, `↑` / `↓`, `PageUp` / `PageDown`, пробел, `Home` / `End`,
стрелка внизу экрана, якоря `#1 … #N`. `about` и `contact` открывают оверлеи,
закрываются по `Esc` или клику мимо.

При `prefers-reduced-motion: reduce` склейки отключаются — фильм играет подряд.

## Локальный запуск

Пока все фильмы с `prerendered: true`, сайт открывается просто двойным
кликом по `index.html` — перемотки нет, значит и сервер не нужен.

Сервер понадобится, как только появится фильм без `prerendered`: такой
движок режет в браузере через `currentTime`, а из `file://` перемотка
не работает.

```bash
cd darina && python3 -m http.server 8000   # → http://localhost:8000
```
