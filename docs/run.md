# Как запустить и посмотреть

## Проще всего: в браузере

Godot не нужен. В репозитории лежит готовая веб-сборка (`build/web`):

```bash
git clone https://github.com/ioshyaxoya/larcheee
cd larcheee && git checkout claude/gaz-chc4j4
cd build/web && python3 -m http.server 8000
# открыть http://localhost:8000
```

Локальный сервер обязателен: браузер не грузит `.wasm` и `.pck` с `file://`.

Ещё вариант — включить GitHub Pages один раз (Settings → Pages → Source:
GitHub Actions). Тогда `.github/workflows/web.yml` сам собирает сборку на каждый
push и публикует по адресу `https://<owner>.github.io/<repo>/` — играть можно
по ссылке, без клона.

## Что нужно, чтобы менять игру

**Godot 4.3+** (Standard, не .NET) — https://godotengine.org/download.
Шрифт IBM Plex Sans лежит в `assets/fonts` (SIL OFL), остальных ассетов нет.

## Играть из редактора

```bash
git clone https://github.com/ioshyaxoya/larcheee
cd larcheee
git checkout claude/gaz-chc4j4
godot --path .            # или: открыть project.godot в Godot и нажать F5
```

Открывается стартовый экран. Слева — битовые часы (20:00, поезд в 20:30),
справа — панель разработчика: происхождение, класс, пол, теги пролога, seed.

| Кнопка | Что делает |
|---|---|
| **Начать «Последние полчаса»** | Сквозной срез: холодное открытие → пролог → возврат в вагон → спор о часах → четыре пути |
| **Сразу в вагон 01 (без пролога)** | Отладочный вход в узел путей: сила, обман, служба, фонарь |
| **Узел путей** | Вернуться к выбору пути |
| **Спор о часах** | Перезапустить испытание Шани |
| **Сохранить / Загрузить** | Единый `world_state.json` (в `user://`) |

**F1** — показать или спрятать панель разработчика. Во время игры она спрятана.

Что можно проверить руками: теги пролога меняют, кто придёт задерживать (без тегов —
Хорипод); масло у святилища меняет первую реплику Шани; проигранный раунд спора
переводит часы на час назад и вагон становится на час раньше; шесть проигранных
раундов — мягкий откат на платформу; фонарь — концовка 5 с титрами.

## Генерация ассетов: разделение труда

Слабое место было названо точно: форму выдумывал кодер из окружностей и
трапеций. Лечится это не более подробным промптом, а разделением труда — и
чужой открытый инструмент это уже решил: [godogen](https://github.com/htdt/godogen)
(MIT, © 2026 Alex Ermolov). Оттуда взяты идея, состав поставщиков, цены и
практические правила; конвейер у нас свой, потому что прямая подстановка
растра сломала бы две наши механики.

```
описание → tools/asset_gen.py → refs/*.png → tools/trace_to_contours.py → data/traced/*.json → движок
```

**PNG в игру не идёт.** У нас цвет каждого контура живёт в данных, и на этом
держатся затухание с глубиной (`dim()`) и закон цвета A10 (`colour_return`).
Запечённая текстура свой цвет несёт с собой и ни тому, ни другому не
подчиняется; лужи света по ней читаются мутью, а не светом. Поэтому генератор
даёт **референс**, а `tools/trace_to_contours.py` превращает его в контуры,
которые движок уже умеет рисовать. Форму больше не выдумывает кодер, конвейер
остаётся один. Растром остаётся только то, что в механике не участвует: key
art, титульный экран, иконки.

- `docs/asset_prompt_template.md` — **источник истины** для стилевого префикса.
  Модель не читала `visual_direction.md`; без префикса выйдет сорок вагонов в
  сорока стилях. `asset_gen.py` читает префикс оттуда и без него не работает.
- `docs/asset_ledger.md` — реестр: чем сделано, сколько стоило, какой размер в
  игровых единицах. Пишется автоматически.
- `.claude/skills/asset-gen/SKILL.md` — порядок работы для агента.
- `tools/requirements.txt` — pillow и numpy нужны только инструментам; игра
  читает исключительно JSON из `data/`.

Что трассировка даёт и чего не даёт: она берёт **массу и раскладку** — силуэт,
поля, украшения. Мелкая черта (лицо, глаз, кайма) на 16 цветах теряется, и её
по-прежнему рисуют скрипты через `tools/draw_lib.py`. Два инструмента
складываются: трассировка ставит массу, кривые доводят черту.

Ключей к генераторам в этой среде нет, поэтому вызовы к Gemini и xAI не
проверены на живых ответах — проверен сбор промпта (`--dry-run`) и вся
трассировка на настоящем референсе (`refs/shani_presence_ref.png` — кадр
присутствия из движка). Первое, что надо проверить с ключами, — режет ли
модерация именно религиозные образы.

## Кадры без экрана (CI, контейнер)

`tests/drive_ui.gd` — драйвер интерфейса: гоняет настоящую сцену, нажимает кнопки,
снимает кадры в `user://shots/`. Пять сценариев: `slice` (срез целиком),
`paths` (пути вагона и концовка 5), `scene` (постановка вагона без интерфейса),
`shani` (встреча с присутствием, включая обход застывшей сцены) и
`glitchcheck` (проверка послойности, см. ниже).

### Присутствие не должно дизериться вместе с миром

Правило §4 и §3.1: точки — только у мира, присутствие остаётся единственным
полностью цветным элементом. Держится это не на памяти, а на измерении:

```bash
godot --path . tests/drive_ui.tscn ++ --scenario=glitchcheck
python3 tools/check_presence_layer.py ~/.local/share/godot/app_userdata/BOMBAY\ MAIL/shots
```

Проверка снимает кадр со сбоем и без сбоя, берёт силуэт из альфы отдельного
подвьюпорта присутствия и требует совпадения пиксель в пиксель внутри силуэта
при том, что мир изменился. Если кто-нибудь однажды упростит конвейер до
одного полноэкранного прохода — проверка упадёт, а не кадр «как-то поедет».

```bash
xvfb-run -s "-screen 0 1280x720x24" godot --path . \
  --display-driver x11 --rendering-driver opengl3 --resolution 1280x720 \
  tests/drive_ui.tscn ++ --scenario=slice
```

Под Xvfb нужен software OpenGL: `LIBGL_ALWAYS_SOFTWARE=1` и заданный
`XDG_RUNTIME_DIR`. Vulkan в контейнере не поднимается, поэтому `--rendering-driver
opengl3` обязателен.

## Как сделан визуал

По `docs/visual_direction.md`: плоский театральный 2.5D (ориентир — Kentucky
Route Zero) и режим испытания как застывшая сцена (ориентир — Return of the
Obra Dinn). Один конвейер, два шейдера:

- `assets/shaders/theatrical.gdshader` — базовый режим: грейдинг по
  `car.palette` (A10), виньетка-кулисы, плёночное зерно, сияние для
  болливудских палитр.
- `assets/shaders/dither_1bit.gdshader` — режим испытания: монохром с
  упорядоченным дизерингом Байера и параметром `colour_return` 0→1. Время
  стоит — цвета нет; каждый выигранный раунд возвращает слой цвета.

Сцена рендерится в подвьюпорт, шейдер лежит на её кадре, интерфейс рисуется
поверх и не грейдится. Постановка вагона — плоские цветовые поля в объёме
(`car.stage`: `layers`, `props`, `pools`), свет описан **лужами** — аддитивными
пятнами, а не светильниками: свет здесь форма, а не физика.

### Рисунок: кривые, а не примитивы

Фигуры и реквизит нарисованы **линиями**. `tools/draw_lib.py` — рисовальная
библиотека: кубические Безье (`bez`, `curve`, `smooth`), симметричный силуэт из
одной линии бока (`mirror`), настоящая линия переменной толщины (`stroke`),
мягкие замкнутые формы (`blob`), проверка контура на самопересечение
(`is_simple`) — движок такой контур не триангулирует, поэтому падаем сразу, в
скрипте, а не молча в кадре.

`tools/draw_car_01.py` рисует этим вагон 01: восемь фигур (у каждой — одна
непрерывная кривая бока, поверх неё голова, одежда, вещь и линии складок) и
пятьдесят предметов. Результат — данные (`data/cars/car_01.json`,
`data/npcs/*.json`); движок (`StageBuilder`) только заливает контуры плоским
цветом. Править форму — в скрипте, не в движке и не руками в JSON.

### Глубина

Вагон — коридор: полки невостребованного уходят дальше, чем позволяет длина
состава (`docs/car_01_brake_van.md` §2), и это первое нарушение геометрии в
игре. Читается это двумя средствами:

- **Длинный объектив.** Камера вагона перспективная (`stage.camera.projection`
  = `perspective`, fov 38). Ортография коридор убивает: параллельные стены
  остаются параллельными, глубины нет. Проекцию выбирает вагон в своих данных —
  сцены, которым нужна ортография, её и получают.
- **Тьма нарисована, а не посчитана.** Плоская заливка не гаснет с
  расстоянием, а туман движка не действует на непросвечиваемый материал.
  Поэтому пол, стены, потолок нарезаны по глубине, и каждый следующий отрезок
  темнее (`dim()` в `tools/draw_car_01.py`); реквизит и фигуры гаснут по своей
  координате. Тьму возвращает фонарь — лужами света, как в театре гасят задние
  планы.

### Встреча с присутствием

Испытание — не разговор с фигурой в глубине вагона. Человек влетел в тормозной
вагон, и его встретило присутствие: **Шани в три человеческих роста на
гигантском вороне**, камера снизу вверх, вокруг — мир Шани. Рисует
`tools/draw_shani.py` (142 контура на присутствие), данные — блок `stage` в
`data/trials/trial_shani.json`.

Иконография не выдумана и проверена по источникам: тёмно-синяя, почти
холодно-чёрная кожа; синие одежды; **тришула**, **лук и стрела**, поднятая
ладонь и рука на колене — четыре руки; **кирита-мукута**; бледный нимб;
большой ворон как вахана. По «Брахма-вайварта-пуране» его взгляд несёт беду
тому, на кого падёт, — поэтому холодный глаз в кадре есть и у ворона.

**У присутствия есть лицо, и оно нарисовано по другому закону, чем весь мир.**
Люди в вагоне — плоские силуэты в один тон. Присутствие — глазурованная
фигура: три тона на каждой форме плюс блик (`glaze()` и тональные пары в
`tools/draw_shani.py`), лицо со взглядом, золото. Оно обязано выбиваться из
кадра как лакированная игрушка среди картона: человек должен понять, что перед
ним не человек, до первой реплики. Это записано в `visual_direction.md` §3.1 —
правило «фигуры без лиц» осталось для людей, присутствия из него выведены.
Мимики нет: лицо неподвижно, и должно быть неподвижным.

Композиция фронтальная, снизу вверх, крылья ваханы раскрыты. **Собака у ног и
человек рядом — не украшение, а масштаб:** без них три человеческих роста не
читаются. Собака та же, что в вагоне (`npc_dog`), — в застывшем миге она тут.

Кадр собирается из **трёх** кадров одного мира — слои видимости, а не оттенки
в шейдере:

| Слой | Что | Как выглядит |
|---|---|---|
| 1 | вагон | уходит в глитч |
| 2 | присутствие: ворон и Шани | **цвет**, поверх всего, не дизерится |
| 3 | мир Шани: белое поле, хребты, река, кольцо Сатурна | точечный растр |

Мир монохромный и точечный, потому что время стоит (§4), а `colour_return`
возвращает цвет по выигранным раундам. Цветной с самого начала только он —
и это работает как задумано: единственное цветное пятно в точечном мире.

**Сбой мира.** Шани сомневается во всём вокруг, и его мир рвётся: полосами
проступают стены вагона — тем же растром, каким нарисован мир. Живёт в
`dither_1bit.gdshader` (`glitch`, `alt_tex`), вспышками, а не постоянной рябью.
Проигранный раунд рвёт мир сильнее, выигранный — держит крепче.

Сцену можно обойти (`visual_direction.md` §5) — камеры испытания отвязаны от
вагона; кадры сбоку и сверху снимает `--scenario=shani`.

### Что делает кадр не кустарным

Это не про количество контуров. Пять вещей, каждая из которых по отдельности
выдаёт работу на скорую руку:

1. **Тень на земле.** Без неё присутствие лежит на фоне наклейкой. Пять
   ступеней тона от края к лапам (`cast_shadow()`), самое тёмное — под лапами.
2. **Виньетка на присутствии.** `assets/shaders/presence.gdshader`: тот же спад
   к краям, что у мира, и десять процентов холодного света сцены на фигуру.
   Присутствие не грейдится в монохром — но оно в кадре, а не на кадре.
3. **Ни одной прямой границы у земли.** Полосы-квадраты давали шов через всю
   ширину кадра. Глубину набирают наплывы с кривым краем (`ground_swell()`).
4. **Светлый мир, тёмные акценты.** Однобитный растр шумит на середине тона,
   поэтому земля и небо держатся в светлом (0,76–0,96), а тёмное отдано малым
   формам: камню, дереву, собаке, тени. Контраст несёт присутствие.
5. **Перо как форма, а не лента.** `plume()` — лист с одной выпуклой стороной и
   светлой кромкой по ней (`plume_edge()`). Лента одинаковой толщины пером не
   выглядит, и крыло из таких лент — чёрная лопасть.

Плюс мелочи того же рода: локоть — складка, а не шарик (шарик читается куклой);
зубцы подола без золота на каждом (с ним подол — воротник шута); древко с
тёмным контуром (без него — водопроводная труба); кончик пера скруглён.

## Движение

Замер до правки: **в вагоне не менялся ни один пиксель** — 0,00% отличия на 90
подряд идущих кадрах. В испытании двигался только сбой мира. То есть игра была
не «почти без анимации», а без анимации вообще, и это видно на любой записи.

Движение задаётся **данными**, как и постановка: у кулисы, предмета, фигуры,
лужи света и у самой камеры может быть блок `motion`
(`src/train/car/stage_motion.gd`). Виды: `sway`/`bob` (качание), `pace`
(расхаживание с задержкой на концах), `turn`, `flicker` (мигание яркости),
`scroll`. На один узел можно положить список движений — смещения складываются.

Почему не AnimationPlayer: анимировать надо сорок вагонов и восемь присутствий,
и делать это должен автор данных, а не кодер сценами. Здесь только вечное
движение — то, которое идёт всегда и говорит «поезд едет».

Что двигается сейчас:

| Где | Что | Зачем |
|---|---|---|
| Вагон | камера качается: 1,2 см и четверть градуса крена, две волны | поезд идёт всегда (§3) |
| Вагон | три лампы качаются, у каждой своя фаза и период | синхронные лампы читаются механизмом, а не подвесом |
| Вагон | топка и лужи света мигают двумя несовпадающими волнами | керосин и уголь не горят ровно |
| Вагон | метла, крюки, доска объявлений — еле заметно | вагон живой, а не макет |
| Испытание | **только присутствие**: ворон расхаживает, голова поводит отдельно | мир застыл — это правило §4, двигается лишь тот, кто вне времени |
| Диалог | реплика набирается по буквам, варианты приходят после | единственное движение, которое есть в каждом кадре |

Замер после правки: вагон **22,7%** отличия от первого кадра (5,9% в среднем
между соседними), испытание — 22,4%. Мерит `--scenario=motion`.

### Запись прохода

- `--scenario=letsplay` — по кадру на реплику, быстро, для разбора.
- `--scenario=film` — непрерывная запись в JPEG 960×540: видно качку, мигание,
  расхаживание ворона и набор текста. Собирает `tools/make_letsplay.py`.

## Чего ещё нет

Звука, экранов мини-игр службы (проходятся по данным), вагонов 2–40. Пролог в
Калькутте идёт текстом над спрятанным вагоном — своей постановки у него пока
нет, а нужен «жаркий и яркий южный город»: улицы и ворота, гхат, святилище,
Хаура, платформа.

## Решение по свету (расходится с документами — нужно подтвердить)

Свет переставлен: вагон теперь **освещённый изнутри разрез** — внутри тепло и
всё читается, тёмное только конструкция и передний план. Персонажи цветные:
кожа, одежда, волосы, вещь в руках. Лиц по-прежнему нет.

Это противоречит двум местам в документах, и их надо привести в порядок:

- `docs/visual_direction.md` §3: «Тьма по умолчанию, лужи света от фонарей,
  окон, печки». Сейчас наоборот: свет по умолчанию, тьма — акцент.
- `docs/car_01_brake_van.md` §2 и ТЗ A10 про `bollywood_dark`: «тьма, тьма,
  тьма — и вдруг золото на один такт». Золотая вспышка на повороте стрелки
  осталась, но фон вокруг неё больше не чёрный.

Режим испытания (монохром с дизерингом и возвратом цвета по раундам) не
менялся: там время стоит, и обесцвечивание работает как задумано.
