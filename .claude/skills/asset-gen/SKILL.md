# Генерация референсов

Этот скилл — не «нарисовать картинку и положить в игру». В игру попадают
**контуры**, а PNG остаётся референсом. Причина механическая, не стилевая:
цвет каждого контура живёт в данных, и на этом держатся затухание с глубиной
(`dim()`) и закон цвета A10 (`colour_return`). Запечённая текстура ни тому, ни
другому не подчиняется. Полностью — `docs/asset_prompt_template.md` §0.

```
описание → tools/asset_gen.py → refs/*.png → tools/trace_to_contours.py → data/*.json → движок
```

## Порядок

1. **Собрать промпт и посмотреть его бесплатно.**
   ```bash
   python3 tools/asset_gen.py --kind presence --dry-run \
     --describe "что именно" -o refs/name.png
   ```
   Стилевой префикс подставляется сам из `docs/asset_prompt_template.md`.
   Руками префикс не писать и в скрипт не копировать — там один источник
   истины, иначе стиль разъедется по сорока вагонам.

2. **Подтвердить расход и сгенерировать.** Каждый вызов — реальные деньги:
   Grok 2¢, Gemini 5–15¢ по размеру. Без `--yes` инструмент останавливается.
   Для присутствий и всего, где важна иконография, — только `--model gemini`:
   Grok красив, но промпт слушает плохо.
   ```bash
   python3 tools/asset_gen.py --kind presence --model gemini --size 1K --yes \
     --describe "..." --size-note "5.2 м высотой" -o refs/name.png
   ```

3. **Посмотреть глазами.** Плохой референс тянет за собой всю трассировку.

4. **Трассировать в контуры.**
   ```bash
   python3 tools/trace_to_contours.py refs/name.png -o data/traced/name.json \
     --height 5.2 --palette shani --preview refs/name_traced.png
   ```
   `--palette` сводит цвета к палитре рисовального скрипта — без этого
   референс принесёт свои цвета и палитра проекта поедет. `--preview` даёт
   PNG уже контурами: сверять надо его, а не исходный референс.

5. **Подключить.** Контуры кладутся в `parts` предмета или фигуры — формат тот
   же, что у рисовальных скриптов, `StageBuilder` читает без изменений.

## Правила, которые нарушать нельзя

- **Прозрачный фон не просить никогда** — модель впечатает шахматку. Просить
  сплошной цвет (`--background`), снимает его трассировщик.
- **Направлению взгляда не верить.** Модели путают «влево/вправо». Генерировать
  одно направление, отражать в данных (`flipped()`).
- **Семья стиля — через `--image`.** Первое присутствие рисуется с нуля и
  становится эталоном; остальные семь — image-to-image от него. С нуля каждое —
  восемь разных стилей.
- **Иконография по источникам, не по памяти** (`visual_direction.md` §3.2).
  Ошибка здесь этическая, а не стилистическая.
- **PNG в `data/` не кладётся.** Исключение — то, что не участвует в механике:
  key art, титульный экран, иконки.

## Если модерация режет

У Gemini и Grok свои политики на религиозные образы. Проверять надо именно на
присутствиях. Если режет — генерировать композицию и атрибуты отдельно, а лицо
рисовать контурами через `tools/draw_lib.py`, как сейчас нарисован Шани.

## Чего здесь нет и почему

3D, риг, видео, `publish.sh` из godogen не переносились: `visual_direction.md`
отменяет 3D low-poly — ригать нечего, а `publish.sh` создаёт новый проект с
нуля вместо встраивания в существующий. Их движковый гид тоже не взят: он про
C#/.NET, а у нас GDScript.
