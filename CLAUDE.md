# BOMBAY MAIL — правила проекта

Изометрическая RPG. Британская Индия, 1890. Шасси — SRD 5.2 (CC-BY-4.0), Godot 4.3+, GDScript.
Полное ТЗ и приложения — в `docs/`. Читай их по указателю, не держи в контексте целиком.

## Неотменяемое

Эти правила не обсуждаются и не «улучшаются». Нарушение = PR не мёржится.

1. **Локальность присутствий.** В поезде едут не «боги Индии» и не пантеон, а восемь локальных присутствий. Пиши «Кали Калигхата», а не «Кали». Запрещено везде, включая маркетинг: «пантеон», «боги Индии», «все боги», «собрать богов», «коллекция божеств».
2. **Присутствия бессмертны.** На нуле HP бог покидает поезд и возвращается. Смерть бога не показывается никогда. Игрок никогда не управляет телом бога.
3. **Не «бой», а «испытание».** Столкновение с присутствием называется испытанием, состязанием или судом. Слова «бой», «убить», «победить бога», «босс» в этом контексте запрещены.
4. **Шуньястра не убивает богов.** Она создаёт зону, куда богу не войти. Формулировки «убивает бога / уничтожает бога» запрещены.
5. **Нет скрытых бросков.** Каждая проверка d20 видна игроку. Комментарий рассказчика, «предвидящий» исход, — флейвор петли, а не скрытая проверка.
6. **Нет принудительных перемещений игрока.** Поезд никого не выталкивает. Единственное исключение — мягкий откат в испытании Шани.
7. **Никакой сексуализации божеств** — в арте, тексте, анимации.
8. **Автор шутки о культуре — всегда персонаж этой культуры**, никогда рассказчик.
9. **Сексуальное насилие не изображается.** Угроза может существовать как факт мира; сцены нет.
10. **Никаких «+2 к мечу».** Вертикальный рост — через уровни, билет и репутацию.

## Порядок работы

- **Одна задача — один вагон — одна ветка — один PR.** Никогда не трогай два вагона в одной задаче.
- Логика вагона живёт **в данных** (`data/cars/*.json`), не в скриптах. Кастомный скрипт — только для уникальной механики, объявляется в `car.custom_script`.
- Любой новый флаг регистрируется в `data/flags.json`. Валидатор падает на незарегистрированном флаге.
- Тексты — ключи, не строки в коде. Русский основной, английский второй.
- Все проверки — через `rules/checks`.
- Реакции NPC пишутся по **осям** (`attitude_axes`: белый/небелый, записанный/незаписанный, кредитоспособный/нет, мужчина/женщина, мундир/лохмотья), не по клеткам происхождение×класс×пол. Уникальные комбо-реплики — только у присутствий и ~10 ключевых NPC, каждая регистрируется в `data/pearls.json`.

## Перед каждым PR

```bash
python tools/term_lint.py .
python tools/car_validator.py data/cars/
python tools/hours_estimator.py data/cars/
godot --headless -s tests/smoke.gd
```

Линтер — не рекомендация. Правила выше живут в CI, а не в надежде, что их прочитали.

## Стек и структура

- Godot 4.3+, GDScript. **Плоский театральный 2.5D** (референс Kentucky Route Zero): плоскости в объёме, силуэты без лиц, свет делает работу. Испытания присутствий — **навигируемая застывшая сцена** (референс Return of the Obra Dinn): камера отстёгивается, время стоит, цвет возвращается по выигранным раундам. Один конвейер, два шейдера. См. `docs/visual_direction.md`.
- Данные — JSON в `data/`. Сохранение — единый `world_state.json`.
- `src/core` состояние и сейвы · `src/rules` SRD-механика · `src/train` вагоны, переходы, окно, хвост · `src/dialogue` · `src/performance` ритм-испытания · `src/palette` грейдинг · `src/gods` · `src/factions` · `src/ui`

## Юридика

- SRD 5.2 под CC-BY-4.0, атрибуция Wizards of the Coast в титрах обязательна.
- Product Identity (D&D, Baldur's Gate, Forgotten Realms и т.п.) не используется нигде.
- Artificer в SRD отсутствует — класс Телеграфиста наш собственный.
- Доктор Харен Маллик, Англо-Арийское общество, Прана-союз — вымышлены. Изобретение оружия не привязывается ни к одному реальному учёному эпохи.

## Документы

- `docs/TZ.md` — основное ТЗ (разделы A1–A20, часть B). Источник истины.
- `docs/synopsis.md` — синопсис с причинными связями.
- `docs/appendix_1_combos.md` — матрица 11 происхождений × 9 классов × 2 пола.
- `docs/appendix_2_characters.md` — механика происхождений и классов.
- `docs/appendix_3_items.md` — каталог предметов (~600).
- `docs/car_01_brake_van.md` — эталонный вагон. Образец для всех остальных.
- `docs/quest_last_half_hour.md` — финальный квест пролога.
- `docs/visual_direction.md` — визуальное направление. Отменяет 3D low-poly из B1.
- `docs/cover_brief.md` — ТЗ на key art.

При конфликте: ТЗ важнее приложений, `CLAUDE.md` важнее всего.
